# 50mm 원형 스티커 인쇄 파일

기준: 원형스티커_인쇄파일_ai_프롬프트.pdf. 결과 화면의 **원형 스티커 인쇄하기** 또는 **이 디자인으로 인쇄 견적 받기**에서 시작합니다. 둥근 사각형의 기존 간편 파일은 유지합니다.

## 화면 흐름

1. 확정 PNG를 자산 ID·SHA-256 버전으로 저장하고 불러옵니다. 브라우저 IndexedDB에 계정별 원본 Blob을 보관합니다. 다른 확정 PNG를 선택할 수도 있습니다.
2. 왼쪽 완성 모양과 오른쪽 인쇄 작업 영역에 같은 PNG를 같은 물리 크기로 배치합니다.
3. 배경·인쇄소명·파일 종류·칼선 별색 이름과 선 굵기를 정합니다.
4. **인쇄 미리보기 만들기**로 검증과 파일 생성을 수행합니다. 이 단계는 온을 사용하지 않습니다.
5. 미리보기를 승인한 뒤 PDF/ZIP 받기 또는 견적 요청으로 이동합니다. 옵션·시안이 바뀌면 생성 파일과 승인을 무효화합니다. 견적 크기·이미지가 바뀌어도 제출을 막고 재확인을 요구합니다.
6. 전달 ZIP에는 선택한 파일만 넣습니다. 인쇄소의 기존 원본 파일 버튼은 ZIP 의뢰에서 인쇄 파일 ZIP으로 표시합니다. 모의 계정은 실제 업체에 보내지 않습니다.

## 규격

| 기준 | 값 |
| --- | --- |
| 템플릿 | circle-50mm-v1 |
| PDF MediaBox | 76×76mm |
| PDF TrimBox | [3, 3, 73, 73]mm, 70×70mm |
| 원형 칼선 | 중심 (38,38)mm, 반지름 25mm, 닫힌 벡터 경로 |
| white | PNG 50×50mm, (13,13)mm, 50mm 원으로 클립 |
| solid | 투명 PNG 50×50mm, 배경 원 반지름 28mm로 3mm 여분 |
| full-bleed | 불투명 PNG 56×56mm, (10,10)mm, 완성 미리보기만 50mm로 클립 |
| 유효 ppi | 원본 가로 px×25.4÷배치 가로 mm |
| 최저 해상도 | 300ppi. 50mm는 591px, 56mm는 662px 이상 |

정사각형 단일 프레임 PNG만 허용합니다. APNG, 비정사각형, 300ppi 미만, solid의 불투명 PNG, full-bleed의 투명 PNG는 생성 전에 차단합니다. 원본 제한은 4096px·20MB입니다.

## 출력

- layout.svg: PNG와 작업·칼선 레이어가 있는 배치 파일.
- artwork.pdf: 인쇄 이미지와 배경만 포함. 칼선·별색·작업 가이드 없음. RGB와 알파 마스크를 손실 없이 압축합니다.
- cutline.pdf: 닫힌 원형 벡터와 칼선 별색만 포함. 래스터 이미지 없음.
- proof.pdf: 완성 모양/작업 영역 2페이지. 각 페이지 76×76mm·TrimBox 70×70mm.
- metadata.json: 자산 ID·버전·페이지·배치·ppi·배경·칼선·요청 파일·승인 시각.

전체 ZIP은 5개 파일을 포함합니다. 전달 ZIP은 인쇄소가 요청한 파일만 포함합니다. 기본 전달은 artwork.pdf, cutline.pdf, proof.pdf, metadata.json입니다. 원형 파일을 기존 60mm 간편 템플릿과 섞지 않습니다.

## 인쇄소 규격과 실제 전달 설정

인쇄소 규격은 화면에서 직접 입력합니다. 기본값은 RGB·CutContour·0.25pt이며 업체 요청을 확인해야 합니다. 업체별 규격 DB 자동 조회는 연결하지 않았습니다. **CMYK는 ICC 프로필 변환을 구현한 것으로 표시하지 않으며, 선택하면 생성하지 않습니다.** 인쇄소가 CMYK 또는 PDF/X를 요구하면 해당 변환과 검수가 필요합니다.

직접 ZIP 업로드에는 Supabase SQL Editor에서 supabase/16_print_files.sql을 한 번 적용해야 합니다. 이번 작업에서 실제 DB에는 적용하지 않았습니다. 이 SQL은 비공개 request-files 버킷에 ZIP과 최대 30MB를 허용하며 읽기·쓰기 정책은 유지합니다. 기존 정책에 따라 요청 소유자와 수락된 인쇄소만 design_path의 ZIP을 읽습니다. 설정 전에는 ZIP을 내려받아 전달할 수 있으며 앱 업로드 실패 시 온 예약은 반환합니다.

미리보기 원본·승인 파일의 브라우저 보관은 기기별입니다. 다른 기기에 원본이 없다면 시안을 다시 확정해 새 버전으로 생성·승인합니다. 실제 제출한 ZIP은 기존 요청 저장소에 보관됩니다. 추가 DB 테이블은 필요하지 않습니다.

## 온 안내

만들기 메뉴의 브랜드·스티커·홍보물 진입, 저장한 브랜드, 초안 이어하기, 이미지 교체, 시즌 생성에 안내창을 표시합니다.

- 브랜드: 30온. 질문 입력·창 진입은 무료, 마지막 생성 실행에 성공하면 사용.
- 스티커·홍보물: 10온. 편집·결과·인쇄 미리보기는 무료. 저장·파일 받기·견적 제출을 실제 완료할 때 작업당 한 번 사용.
- 이미 사용한 초안·현재 작업: 0온으로 표시하고 중복 차감하지 않음.
- 시즌: 프로 무료, 그 외 10온.
- 안내창을 닫거나 취소하기만 하면 잔량은 변하지 않음.

사용량은 pricing.js에서 가져옵니다.

## 구현과 검증

- sticker-print-core.js: 규격·검증·SVG·분리 PDF·ZIP 생성. 외부 npm 의존성 없음.
- sticker-print.js: 원본 버전 저장, 미리보기·승인·다운로드·전달.
- app.js/commerce.js: 진입 온 안내와 결과 연결.
- print.js: 승인 ZIP의 실제 견적 업로드·인쇄소 받기.
- supabase/16_print_files.sql: 선택적 ZIP 업로드 설정.

node --test tests/sticker-editor.test.cjs tests/commerce.test.cjs tests/commerce-exports.test.cjs tests/commerce-flow.test.cjs tests/sticker-print.test.cjs

JavaScript 34개 + Python 20개 통과. 인쇄 검사 11개는 50/56mm 배치, 591/662px 경계, PNG/APNG, 배경 모드, ICC 없는 CMYK 차단, PDF 실측·분리·참조·바이트 오프셋, 두 슬롯 이미지 일치, 버전/옵션 승인 키, ZIP CRC·파일 선택을 확인합니다.

Edge에서 30/10/0온 안내, 원본 버전·812.8ppi, 두 슬롯, PDF 3종·전체 ZIP 받기, 배경 변경 후 승인 해제, 투명 full-bleed 차단, 모의 견적의 승인 파일 4개 전달·재다운로드, 140온 유지까지 확인했습니다. 실제 ZIP의 5개 파일·CRC·승인 메타데이터와 선택 ZIP의 4개 파일을 검사했습니다. 생성 PDF는 Windows PDF 렌더러로 2페이지를 이미지로 변환해 한글·이미지·칼선·3mm 배경 여분을 확인했습니다.

실제 유료 AI·실물 인쇄·ICC 변환·SQL 실행·실제 업체 주문 제출은 검증에 포함하지 않습니다.
