## 1. 제품 개요

### 1.1 문제와 대상
- 대상: 디자인 경험이 없는 소상공인(음식점, 카페, 베이커리, 꽃집 등 업종 제한 없음)
- 문제: 가게 캐릭터, 스티커, 포장 디자인을 외주로 맡기기엔 비용과 시간이 부담됨
- 해결: 가게 정보를 입력하면 AI가 캐릭터를 그리고, 스티커, SNS 이미지, 포장 미리보기까지 바로 쓸 수 있는 파일로 만들어 줌

### 1.2 핵심 사용 흐름
1. 가게 이름으로 시작(현재) / 아이디, 비밀번호 로그인(출시)
2. 가게 정보 입력: 상호명, 업종, 위치, 분위기, 고객층, 특징
3. AI 캐릭터 생성, 색상 선택 또는 내 이미지 업로드
4. 스티커 편집: 상호명, 문구, 모양, 색상, 글자 크기
5. 결과물: 포장 목업 확인, 스티커/SNS/포장 PNG 다운로드, 내 브랜드 저장

### 1.3 범위 밖 (이번 PRD에서 다루지 않음)
- 인쇄 주문, 인쇄소 연결, 결제 정산
- 다국어

## 4. 화면별 명세

### S01 시작
- 사용자 행동: 예시 브랜드 쇼핑백을 옆으로 넘겨 봄, 가게 이름 입력 후 시작
- 입력 필드: 가게 이름(필수, 1~24자)
- 검증: 공백만 입력하면 "가게 이름을 적어주세요." 표시, 입력칸 빨간 테두리, `aria-invalid`
- 버튼: 내 브랜드 만들기(주 버튼)
- 전환: 성공 시 S06
- 출시 버전: 아이디, 비밀번호 로그인 폼으로 바뀌고 가게 이름은 S05 온보딩에서 받음

### S02 회원가입 / S03 로그인 / S04 비밀번호 재설정 (출시)

| 항목 | 명세 |
|---|---|
| 입력 | 아이디(영문 소문자, 숫자, 4~20자, 소문자로 저장), 비밀번호(8~64자, 영문+숫자), 비밀번호 확인, 약관 동의(필수 2개, 선택 1개) |
| 검증 | 입력 중이 아니라 칸을 벗어날 때 검사. 제출 시 첫 오류 칸으로 포커스 이동. 비밀번호 확인 불일치는 확인 칸 아래 표시 |
| 아이디 중복 | 칸을 벗어날 때 서버에 확인, "이미 쓰고 있는 아이디예요." 표시. 가입 제출 때 한 번 더 확인 |
| 로그인 실패 | "아이디 또는 비밀번호가 맞지 않아요." 어느 쪽이 틀렸는지 알려주지 않음 |
| 무차별 대입 방지 | 같은 아이디로 5회 연속 실패하면 5분 잠금, 잠금 안내 문구 표시 |
| 로그인 유지 | 기본 켬. 공용 기기용으로 끄는 체크박스 제공 |
| 복구 코드 발급 | 가입 완료 직후 복구 코드 1개를 한 번만 보여줌. 복사, 이미지로 저장 버튼 제공. "저장했어요" 체크 전에는 다음으로 못 감 |
| 비밀번호 재설정 | 아이디 + 복구 코드 + 새 비밀번호 입력 → 성공하면 새 복구 코드를 다시 한 번만 보여줌(이전 코드는 폐기) |
| 재설정 실패 | "아이디 또는 복구 코드가 맞지 않아요." 같은 아이디로 5회 실패하면 15분 잠금 |
| 버튼 상태 | 제출 중 비활성 + 스피너, 중복 제출 방지 |

### S06 홈
- 표시: 인사말, 새 브랜드 만들기, 이어서 만들기(임시 저장이 있을 때), 남은 AI 생성 횟수, 최근 작업 3개
- 빈 상태: 최근 작업이 없으면 "아직 저장한 브랜드가 없어요. 첫 브랜드를 만들어보세요."
- 새 브랜드 만들기: 임시 저장을 지우고 S07로 이동. 출시 버전은 임시 저장이 있으면 "작업 중인 브랜드가 있어요. 새로 시작할까요?" 확인 창

### S07 가게 정보 입력

| 필드 | 필수 | 형식 | 검증 문구 |
|---|---|---|---|
| 가게 이름 | 예 | 1~24자 | 가게 이름을 적어주세요. |
| 업종 | 예 | 1~100자, 자유 입력 | 어떤 가게인지 적어주세요. |
| 위치(경산시 동) | 아니요 | 목록 선택 | 없음 |
| 분위기 | 예(기본값 있음) | 3개 중 1개 | 없음 |
| 주요 고객층 | 예(기본값 있음) | 3개 중 1개 | 없음 |
| 특징 | 아니요 | 0~120자, 글자 수 표시 | 없음 |

- 버튼: 예시 입력(보조), 브랜드 콘셉트 미리보기(주 버튼, 다음 단계)
- 서버 검증: 같은 길이 규칙을 server.py `validate()`에서 다시 검사함(현재 구현됨)

### S08 AI 캐릭터 생성
- 표시: 캐릭터 미리보기(상단), AI 배지, 상태 안내, AI 생성 버튼(보라), 콘셉트 요약, 동네 같은 업종 정보(접힘), 색상 3종, 내 이미지 업로드
- 버튼: AI로 새 캐릭터 만들기, 이전, 이 브랜드로 만들기
- 업로드 검증: PNG/JPG/WebP, 2MB 이하. 위반 시 토스트 후 선택 취소
- 상태별 UI는 5장, 생성 파이프라인은 6장 참고

### S09 스티커 편집
- 입력: 상호명(1~24자), 문구(0~40자), 모양(원형/둥근 사각형), 색상 3종, 상호명 크기(36~80)
- 미리보기: 쇼핑백에 붙은 스티커가 입력에 맞춰 즉시 바뀜
- 검증: 상호명이 비면 다음 단계로 못 감, 토스트 후 상호명 칸에 포커스

### S10 결과물
- 표시: 포장 목업(쇼핑백/상자 전환), 결과물 카드 3장(스티커 800px, SNS 1080px, 포장 1080px)

## 6. AI 생성 파이프라인

### 6.1 요구사항

| 항목 | 현재 상태 | 중요도 | 난이도 | 선행 조건 |
|---|---|---|---|---|
| 생성 중 로딩, 진행 단계 표시 | 부분: 목업만 3단계, 실제는 문구만 | P0 | 하 | 없음 |
| 버튼 연타, 중복 요청 방지 (클라이언트 잠금 + 요청 ID) | 완료 | P0 | 하 | 없음 |
| 동시 생성 제한 | 부분: 서버 전체 1건 | P1 | 중 | 사용자 식별 |
| 작업 상태 조회 (비동기 작업 + 폴링) | 미구현: 요청 하나로 최대 180초 대기 | P1 | 중 | DB의 generation_jobs 테이블 |
| 실패 복구 (다시 시도, 새로고침 후 결과 받기) | 부분: 다시 시도 버튼만 | P1 | 중 | 작업 상태 조회 |
| 사용자별 생성 횟수 제한 | 부분: 실행당 20회, 브라우저 5회 | P0(출시) | 중 | 인증 |
| 월 비용 상한 | 미구현 | P0(출시) | 하 | 공급자 대시보드 한도 설정 |
| 같은 캐릭터 유지 재생성 (시안 여러 개) | 미구현 | P2 | 상 | 이미지 편집 API 검토 |
| 프롬프트 주입 방지 | 완료: 입력을 JSON으로 감싸 "설명으로만 다룰 것" 지시 | P0 | 하 | 없음 |
| 생성 결과 검사 (PNG 시그니처, 24MB 상한) | 완료 | P0 | 하 | 없음 |

### 6.2 출시용 흐름 (작업 큐 방식)
1. 클라이언트: `POST /api/generations` (요청 ID 포함) → 서버가 횟수, 비용 한도, 동시 작업을 확인하고 `generation_jobs`에 `queued`로 기록, 즉시 `202 {job_id}` 응답
2. 작업자: `queued` → `running` → 공급자 호출 → 이미지를 Storage에 올리고 `succeeded` 또는 `failed`
3. 클라이언트: `GET /api/generations/{job_id}`를 3초 간격으로 조회(최대 4분). 화면을 떠났다 와도 job_id로 이어서 조회
4. 같은 요청 ID가 다시 오면 새 작업을 만들지 않고 기존 job_id를 돌려줌

### 6.3 과금 보호
- 횟수 차감 시점: `running`으로 바뀔 때 1회 차감. 공급자 오류(4xx 중 사용자 입력 문제 제외, 5xx)로 실패하면 되돌림
- 타임아웃: 공급자 호출 180초. 타임아웃이 나도 공급자 쪽 과금이 생길 수 있으므로 자동 재시도하지 않음(현재 원칙 유지)
- 한도: 사용자별 하루 5회, 월 30회(초안 값, 비용 검토 후 확정), 서비스 전체 일 단위 상한
- 공급자 대시보드의 월 사용 한도를 별도로 설정해서 코드 오류에도 상한을 둠
- API 키는 서버 환경변수에만 둠. 로그에 입력, 키, 응답 본문을 남기지 않음(현재 원칙 유지)

### 10.2 Supabase 연동 검토

| 기능 | 쓰는 것 | 메모 |
|---|---|---|
| 복구 코드 | Python 백엔드 | 코드 검증과 비밀번호 변경은 서버에서 Supabase 관리자 API로 처리. 브라우저에서 직접 하지 않음 |
| 인증 | Supabase Auth | 아이디 로그인을 기본 기능으로 제공하지 않음. 아이디를 내부용 주소(`{아이디}@users.gageon.invalid`)로 바꿔 이메일 방식에 넣고, 이메일 확인 기능은 끔. 화면에는 아이디만 보임. 실제 메일이 가지 않으므로 메일 재설정은 쓸 수 없음 |
| DB | Postgres + RLS | 모든 테이블에 `user_id = auth.uid()` 정책 |
| 파일 | Storage, 비공개 버킷 | 다운로드는 짧은 만료 시간의 서명 URL |
| 프런트 | supabase-js (CDN) | index.html 구조 유지 가능. anon 키만 브라우저에 둠 |
| AI 호출 | Python 백엔드 | Supabase JWT를 검증한 뒤 생성. 서비스 키와 OpenAI 키는 서버에만 둠 |

### 10.3 Python 백엔드 배포
- 현재 server.py는 표준 라이브러리 HTTP 서버이고 localhost 전용(`trusted()`)이라 그대로 배포할 수 없음
- 안: FastAPI로 옮기고 Cloud Run, Render, Fly.io 중 하나에 컨테이너 배포. 정적 화면은 GitHub Pages 유지, API만 별도 도메인
- 바꿀 점: Host 고정 대신 CORS 허용 목록, 세션 토큰 대신 Supabase JWT, 메모리 결과 캐시 대신 generation_jobs 테이블, 실행당 20회 대신 사용자별 한도
- 유지할 점: 입력 길이 검증, 본문 8KB 제한, 프롬프트 감싸기, PNG 검사, 자동 재시도 없음, 민감 정보 로그 금지

| 이용약관, 개인정보 처리방침 | 미구현 | P1 |

## 11. 데이터 모델 (출시용 초안)

```
users            Supabase auth.users (id, email = 내부용 주소, created_at)
recovery_codes   user_id(unique), code_hash, created_at, failed_count, locked_until
profiles         id = users.id, username(unique, 소문자), nickname, marketing_agree, created_at, deleted_at
shops            id, user_id, name, industry, dong, created_at
brands           id, user_id, shop_id, name, mood, audience, feature,
                 theme, shape, message, font_size, mockup,
                 character_image_id, sticker_image_id, thumb_image_id,
                 created_at, updated_at
brand_versions   id, brand_id, snapshot(jsonb), created_at          (P2)
generation_jobs  id, user_id, brand_id, request_id(unique), status
                 (queued/running/succeeded/failed/canceled), prompt_input(jsonb),
                 model, error_code, image_id, charged(bool),
                 created_at, started_at, finished_at
images           id, user_id, kind(character/upload/sticker/thumb/sns/pack),
                 storage_path, width, height, bytes, mime, created_at
usage_counters   user_id, period(day/month), period_start, used, limit
```

- 복구 코드 규칙
  - 형식: 헷갈리는 글자(0/O, 1/I/L)를 뺀 대문자와 숫자 16자, 4자씩 하이픈으로 구분(예: `K7QM-3XRT-9PWD-H2NF`)
  - 서버가 암호학적 난수로 만들고 원문은 저장하지 않음. 비밀번호와 같은 방식(bcrypt 또는 argon2)으로 해시만 저장
  - 계정당 1개만 유효. 재설정에 쓰거나 마이페이지에서 재발급(현재 비밀번호 확인 필요)하면 이전 코드는 바로 폐기
  - recovery_codes 테이블은 RLS로 브라우저 접근을 전부 막고 서버(서비스 키)만 읽고 씀
  - 비밀번호와 복구 코드를 둘 다 잃으면 계정을 되찾을 방법이 없음. 가입 화면과 복구 코드 화면에 이 내용을 적음
- 모든 테이블에 `user_id` 기반 RLS. `generation_jobs`의 상태 변경과 `usage_counters` 차감은 서버(서비스 키)만 가능
- 현재 `localStorage`의 브랜드 객체 필드(name, industry, mood, audience, feature, theme, shape, message, fontSize, mockup, customImage)를 그대로 brands로 옮길 수 있음. customImage(data URL)는 images 행 + Storage 파일로 바꿈
- 탈퇴 시 삭제 순서: Storage 파일 → images → generation_jobs → brands → shops → profiles → auth 사용자

## 13. 범위 구분

### 13.1 해커톤 MVP (11/20~21 시연)
원칙: 시연 흐름이 끊기지 않게 하는 것만. 계정, 클라우드는 발표 자료의 로드맵으로 설명함.

|---|---|---|---|

| AI 생성 시연 | 부분: 로컬 서버에서만 실제 생성 | 노트북에서 server.py + OpenAI 키로 실제 생성(확정). 아래 준비 항목 참고 | 하 |
| 뒤로가기, 이어서 만들기 | 완료 | 실기기 점검 | 하 |

시연용 실제 AI 생성 준비 (확정 사항)
- 화면은 노트북 브라우저에서 `http://127.0.0.1:8000`으로 열어야 함. server.py가 localhost 접속만 받기 때문에 휴대폰이나 GitHub Pages 링크에서는 목업으로 동작함
- OpenAI 개발자 계정에 결제 수단 등록, 잔액 충전, 이미지 모델 접근 권한 확인. ChatGPT 구독과는 별도 과금
- OpenAI 대시보드에서 월 사용 한도를 낮게 설정(예산은 팀이 정함)
- 리허설 때 실제로 3회 이상 생성해서 응답 시간을 재고, 결과 이미지를 따로 저장해 둠
- 행사장 네트워크가 끊길 때를 대비해 목업 모드로 바로 바꾸는 방법(키 없이 서버 재시작)을 시나리오에 넣음
- 서버 실행당 20회 제한이 있으므로 리허설 후 서버를 다시 켜고 시연함

### 13.2 실제 서비스 출시 전 필수 (P0/P1)
- 아이디, 비밀번호 회원가입과 로그인(Supabase Auth), Postgres(RLS), Storage 연동
- FastAPI 백엔드 배포, 작업 큐 방식 AI 생성, 사용자별 횟수와 비용 상한
- 클라우드 저장, 더 보기, 썸네일 분리, 지연 로딩
- 회원 탈퇴, 약관, 개인정보 처리방침, 오류 추적, 백업
- 768px, 1280px 레이아웃, 접근성 점검

### 13.3 확장 (P2)
- 같은 캐릭터 유지 재생성, 시안 여러 개 비교
- 버전 관리, 검색, 정렬
- 결제와 크레딧, 관리자 화면
- 인쇄용 파일(300dpi, 재단선), 인쇄소 연결
- 상권 정보 지역 확대
