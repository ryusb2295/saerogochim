# 가게온 온·스티커 시연

최신 기준은 `수정사항2.pdf`의 4개 항목입니다. 이전 경영팀 문서와 다른 부분은 이번 목록을 우선합니다. 새 결제는 모두 모의 결제이며 실제 카드 정보를 받지 않습니다.

## 수정사항2 반영표

| 항목 | 반영 내용 |
| --- | --- |
| 홈 잔량 → 마이페이지, 토큰 → 온 | 홈의 잔량·충전 행을 제거했습니다. 마이페이지에 남은 온·요금제·충전·사용 내역을 표시합니다. 화면의 재화 이름을 온으로 통일합니다. |
| 스티커 이미지 출처 확장 | 홈 만들기 → 스티커 만들기에서 저장한 브랜드 / 내 이미지 첨부 / 가게온 이미지를 고릅니다. 저장한 브랜드가 없어도 시작할 수 있습니다. 편집 중 이미지 교체도 지원합니다. |
| 사용하지 않은 작업 차감 방지 | 편집창 진입, 문구 수정, 이동·색상·글꼴 변경, 결과 미리보기, 견적 폼 열기는 무료입니다. 실제 저장·파일 생성·견적 제출에 성공하면 해당 작업에 10온을 한 번 확정합니다. 같은 작업에서 추가 파일을 받거나 다시 편집해도 중복 차감하지 않습니다. |
| 다운로드 별도 결제 제거 | PNG·SVG·PDF·메뉴판·쿠폰 받기에서 패키지 구매창을 열지 않습니다. 온이 충분하면 바로 파일을 만듭니다. 부족할 때만 온 충전 안내 후 이어서 실행합니다. |
| 새 브랜드 생성 시점 | 질문 입력과 단계 이동은 무료입니다. 마지막 ‘브랜드 만들기 · 30온’ 또는 명시적 재생성 버튼에서만 생성 비용을 사용합니다. 실패하면 반환합니다. 생성한 작업의 저장·다운로드는 추가 10온 없이 이용합니다. |
| 캐릭터 상단 크기 조절 | 미리보기의 캐릭터를 클릭하면 위에 크기 슬라이더와 −/+ 버튼이 나타납니다. 기존 하단 크기·회전 도구도 유지하고 서로 동기화합니다. |

‘들어가서 아무것도 사용하지 않으면 차감하지 않는다’는 조건에 따라 진입 때 실제 잔액을 깎는 대신 사용 완료 때 차감합니다. 새 작업은 이미지 출처에서 다시 시작하거나 저장한 브랜드를 새로 열 때 구분합니다. 초안을 이어 여는 경우는 같은 작업으로 유지합니다. 저장·다운로드 실패는 차감 예약을 반환합니다.

## 이미지와 편집

- PNG·JPG·WebP, 2MB 이하의 이미지를 첨부할 수 있습니다. 정상적으로 열리는 이미지만 최대 1024px로 줄여 편집에 사용합니다. 원본 파일은 변경하지 않습니다.
- 가게온에 포함된 동글 오리·상품·파스텔·선화·가게 이미지를 제공합니다.
- 상호명·문구는 클릭 또는 요소 선택 후 Enter로 수정합니다. 6px 이상 움직이면 드래그로 구분합니다.
- 포장에 붙여 보기, 12종 글꼴, 통합 색상 선택기, 자유 이동·회전과 1600px 스티커 PNG를 유지합니다.
- 원형 인쇄는 새 50mm 규격으로 분리 PDF·승인 절차를 사용합니다. 기존 둥근 사각형의 간편 칼선은 60mm 시연 규격입니다. 자세한 내용은 [원형 인쇄 안내](STICKER_PRINT.md)를 확인하세요.

## 파일과 데이터

| 파일 | 담당 |
| --- | --- |
| `pricing.js` | 요금제·온 가격, 사용량, 수수료, 시즌 기준. 이전 패키지 값은 기존 구매 내역 호환용으로 유지합니다. |
| `commerce-store.js` | 계정별 잔량·원장·구독·구매·주문·정기배송 |
| `commerce.js` | 사용 확정, 실패 반환, 충전·구독, 마이페이지, 정산·시즌 화면 |
| `app.js` | 이미지 선택창, 무료 편집·미리보기, 명시적 생성과 파일·저장 완료 결과 |
| `sticker-editor.js` | 클릭 편집, 드래그, 상단/하단 크기 조절 |
| `commerce-exports.js` | 캐릭터·메뉴판·쿠폰 PNG, 칼선 SVG·PDF |
| `print.js` | 실제 견적 제출 성공/실패 반환, 인쇄비 모의 결제·수수료 |
| `supabase/14_commerce_demo.sql` | 선택 사항: 기기 간 동기화 RPC·접근 제한 |
| `supabase/15_commerce_demo_schedule.sql` | 선택 사항: pg_cron 월별 모의 주문·온 한도 갱신 |

기존 계정과 잔액·구독·구매 내역은 유지합니다. 저장 키와 RPC 필드의 `tokenBalance`, `tokens`, `appliedDesigns` 등 내부 이름은 기존 데이터 및 DB와의 호환을 위해 유지합니다. 새 작업의 사용 확정은 `appliedDesigns['use-v2:'+commerceSessionId]`에 기록합니다.

## 유지한 경영팀 시연 기능

- 가입 무료 150온 1회, 라이트 월 9,900원·300온, 프로 월 19,900원·1,000온, 100/500온 충전. 월 갱신은 이월 없이 한도까지 채우고 해지는 다음 갱신부터 적용합니다.
- 인쇄소 수수료 8%, 사장님 이용료 0원. 92,000원 주문은 수수료 7,360원·정산 84,640원이며 수령 확인 전에는 정산 예정으로 표시합니다.
- 완료 주문 재주문은 디자인·규격·재질·후가공·배송지·인쇄소를 복사하고 수량·납기만 수정합니다.
- 프로 정기배송과 이번 회차 실행은 별도의 모의 주문입니다. 회차별 인쇄비는 별도로 모의 결제합니다.
- 30일 이내 시즌을 제안합니다. 기존 캐릭터에 계절 문구를 조합하는 시연이며 프로는 무료, 다른 요금제는 10온입니다. 시즌 시안에서 인쇄 요청으로 넘어가도 사용 비용을 다시 차감하지 않습니다.

초기화는 요금제의 ‘수익화 시연 상태 초기화’ 또는 로그인 상태의 `await resetDemo()`입니다. 현재 계정의 수익화 시연 정보만 초기화합니다.

## 확인 순서

1. 마이페이지의 150온을 확인합니다. 홈에는 잔량 표시가 없습니다.
2. 만들기 → 스티커 만들기 → 가게온 이미지에서 이미지를 고릅니다.
3. 캐릭터를 클릭하고 상단 + 버튼을 눌러 하단 슬라이더와 함께 바뀌는지 확인합니다. 문구를 클릭해 고치고 결과물 보기로 이동합니다.
4. 마이페이지 잔량이 그대로인지 확인합니다. 홈의 이어서 만들기로 돌아가 PNG를 받으면 140온, 같은 작업에서 PDF도 받아도 140온입니다. 패키지 결제창이 나오지 않습니다.
5. 내 이미지 첨부와 저장한 브랜드에서도 같은 편집 흐름으로 진입합니다.
6. 새 브랜드의 질문 입력만 하고 나오면 차감이 없습니다. 마지막 생성 버튼으로 성공한 경우 30온만 사용하며 파일 받기에 추가 비용이 없습니다.

## 검증과 한계

자동 검사:

```powershell
node --test tests/sticker-editor.test.cjs tests/commerce.test.cjs tests/commerce-exports.test.cjs tests/commerce-flow.test.cjs
python -m unittest -q test_server.py
```

- JavaScript 22개: 기존 스티커·구독·주문·PDF 검사와 새 작업 미사용/사용 확정/중복 방지/실패 반환/계정 전환/생성 비용 검사.
- Python 서버 19개.
- 브라우저 확인: 홈 잔량 제거, 마이페이지 온, 기본 이미지 선택, 문구 클릭 편집, 상단 +와 하단 110% 동기화, 편집·미리보기 후 150온 유지, PNG 후 140온, PDF 추가 후 140온 유지, 패키지 결제창 제거.
- 브라우저의 로컬 파일 선택은 선택창 진입까지만 확인했습니다. 실제 PNG·JPG·WebP 파일 첨부와 모바일 터치는 추가 확인 대상입니다. 실제 유료 AI 호출은 이번 검증에 포함하지 않았습니다.
- SQL 14·15는 이번 작업에서 Supabase에 적용하지 않았습니다. 미적용 상태에서도 계정별 브라우저 저장으로 시연합니다. 다른 기기 동기화와 앱을 닫았을 때 월별 자동 실행은 SQL·pg_cron 설정이 필요합니다.
- 실제 PG·은행 정산·실물 제작 접수는 연결하지 않았습니다. 모의 결제와 시연 주문입니다. 기존 견적·채팅·AI 한도는 유지합니다.
