# 경영팀 수익화 기능 시연

`gageon_dev_handoff.pdf`의 7가지 수익모델과 스티커 클릭 편집을 구현했습니다. 모든 신규 결제는 `commerce.js`의 `mockCheckout` 내부의 모의 결제이며 카드 정보를 받지 않습니다. 기존 인쇄비 결제도 카드 결제창 대신 같은 시연 결제로 진행합니다.

## 파일과 구조

| 파일 | 담당 |
| --- | --- |
| `pricing.js` | 패키지·요금제·토큰 가격, 차감량, 수수료, 시즌 캘린더, 시연 단가 |
| `commerce-store.js` | 계정별 잔량·원장·구독·구매·주문·정기배송 상태, 월 갱신과 재주문 계산 |
| `commerce.js` | 기존 모달·바텀시트 스타일로 구매·충전·요금제·원장·주문·시즌 제안 연결 |
| `commerce-exports.js` | 캐릭터, 메뉴판, 쿠폰, 칼선 SVG·PDF 다운로드 |
| `app.js`, `sticker-editor.js` | 기존 화면 연결, 클릭과 드래그 구분, 텍스트 편집·토큰 반영 |
| `print.js` | 인쇄비 시연 결제, 소상공인 비용 표시, 인쇄소 수수료·정산 표시 |
| `supabase/14_commerce_demo.sql` | 선택 사항: 계정 상태와 시연 주문의 기기 간 동기화 RPC·접근 제한 |
| `supabase/15_commerce_demo_schedule.sql` | 선택 사항: pg_cron을 통한 매월 1일 모의 주문·한도 갱신 |

가격을 바꿀 때는 `pricing.js`만 수정합니다. 주문에는 생성 당시 금액·수수료를 기록합니다. 이미 구매한 패키지는 차액으로 업그레이드합니다. 브랜드 패키지는 라이트 한 달을 지급하며 이미 프로를 쓰는 계정을 라이트로 낮추지 않습니다.

## 구현된 흐름

1. 다운로드·저장 버튼을 누르면 미구매 브랜드의 패키지 선택창이 열립니다. 개업 패키지가 기본 선택입니다. 스타터는 캐릭터와 기본 스티커만, 개업은 기본+세트 2종과 포장·SNS·칼선 파일, 브랜드는 메뉴판·쿠폰을 추가로 받습니다. 구매는 브랜드 식별자별로 유지됩니다. 미리보기는 무료입니다.
2. 마이페이지에 토큰 잔량·요금제·충전·원장을 표시합니다. 가입 토큰은 계정당 한 번만 지급하며, 구독은 매월 한도까지 다시 채웁니다. 해지는 다음 갱신일부터 적용하고 무료 가입 토큰을 재지급하지 않습니다.
3. 생성은 30토큰, 문구·홍보물 반영은 10토큰입니다. 키 입력·미리보기·이동·색상·글꼴은 무료이며 명시적인 반영·내보내기 단계에서 변경된 텍스트만 과금합니다. 실패 시 차감 예약을 한 번만 반환합니다. 부족할 때 충전하면 원래 작업이 이어집니다.
4. 스티커의 상호명·문구를 한 번 클릭하면 편집창이 열립니다. 6px 이상 움직이면 드래그로 처리하여 이동할 때 편집창이 열리지 않습니다. 요소 선택 후 Enter로도 수정할 수 있습니다.
5. 같은 인쇄 주문을 사장님은 견적 금액+이용료 0원으로, 인쇄소는 거래액−8% 수수료로 봅니다. 예: 92,000원→7,360원 수수료→84,640원 정산. 수령 확인 전에는 정산 예정으로 표시합니다.
6. 납품 완료 의뢰를 재주문하면 디자인·규격·재질·후가공·배송지·인쇄소를 복사합니다. 확인창에서 수량·납기만 바꾸고 바로 시연 결제 대기 주문을 만듭니다. 프로는 정기배송을 신청하고 회차를 실행할 수 있습니다. 회차별 인쇄비를 별도로 결제하며 수수료도 다시 계산합니다.
7. 홈에 30일 이내 시즌을 제안합니다. 기존 캐릭터와 계절 문구를 조합한 시연 이미지이며 프로는 무료, 무료·라이트는 10토큰입니다. 시안 보기 또는 PNG가 채워진 견적 폼으로 이동합니다.

## 3분 시연 순서

1. 기존 체험 계정으로 브랜드를 열고 문구를 클릭해 수정합니다. 반영 후 마이페이지에서 토큰 내역을 확인합니다.
2. 다운로드에서 패키지 선택창을 보여주고 브랜드 패키지를 모의 결제합니다. PNG·SVG·PDF를 받고 라이트 300토큰 지급을 확인합니다.
3. 마이페이지→요금제에서 프로를 모의 구독합니다. 시연 주문→납품 완료 예시 넣기→같은 디자인으로 다시 주문을 누르고 수량·납기를 확정합니다.
4. 모의 인쇄비를 결제하고 정기배송을 신청한 뒤 이번 회차를 실행합니다. 마이페이지의 인쇄소 정산 시연에서 같은 주문의 수수료를 확인합니다.
5. 홈에서 무료 시즌 시안을 확인하고 ‘이 시안으로 인쇄 견적 받기’를 눌러 이미지가 전달되는 것을 보여줍니다.

초기화: 요금제 화면의 ‘수익화 시연 상태 초기화’ 또는 로그인 상태의 `await resetDemo()`. 현재 계정의 수익화 시연 데이터만 초기화하고 기존 브랜드·실제 견적·채팅은 지우지 않습니다.

## 검증

- `node --test tests/sticker-editor.test.cjs tests/commerce.test.cjs tests/commerce-exports.test.cjs`: 16개 통과.
- `python -m unittest -v test_server.py`: 새 정적 스크립트를 포함한 20개 통과.
- Edge에서 문구·상호명 클릭, 10토큰 반영, 스타터 잠금·브랜드 차액 업그레이드, 300토큰 지급, 100토큰 충전, 프로 1,000토큰, 재주문·모의 결제·정기배송 회차, 소상공인·인쇄소 금액, 시즌 시안의 견적 폼 전달, 일반 로그인 경로를 확인했습니다.
- 잔량 10→생성 시 충전 안내→100 충전→자동 생성 재개→80 잔량 및 원장을 확인했습니다.
- PNG를 실제 내려받아 1600×1600 크기를 확인했습니다. 실제 PDF 다운로드의 헤더·칼선 색상과 PDF 바이트 오프셋 검사를 확인했습니다.

## 배포 전에 필요한 설정과 한계

- DB SQL은 저장소에 준비했으며 이번 작업에서 실제 Supabase 프로젝트에 적용하지 않았습니다. SQL Editor에서 기존 스키마 뒤에 14번을 적용하면 RPC를 통해 계정별로 동기화합니다. 미적용 시 이 브라우저 안에서 계정별로 저장하며 화면에도 그렇게 표시합니다.
- 앱이 닫힌 동안의 월별 실행은 pg_cron 활성화와 15번 SQL 적용이 필요합니다. 미설정 시 앱을 열거나 다시 활성화할 때 도래한 회차를 처리하고 ‘이번 회차 지금 실행’ 버튼으로 시연합니다. 달력에는 현재 양력 시즌을 등록했으며 음력 명절 날짜는 추후 추가할 수 있습니다.
- 재주문·정기배송은 실제 인쇄소로 발주하는 대신 별도 시연 주문에 생성합니다. 실제 의뢰·채팅은 기존 기능을 유지합니다. 기존 실제 의뢰의 모의 결제 완료 표시는 기존 `mark_paid` RPC를 재사용합니다.
- 기존 연결 체험 계정의 소상공인 마이페이지와 인쇄소 주문·정산 금액 조회도 확인했습니다. 새 DB SQL 미적용 시 브라우저 저장으로 돌아오는 것을 확인했습니다.
- 실제 AI는 기존 관리자 승인·서버 호출 한도를 유지합니다. 시연 구독이나 토큰 충전으로 실제 AI 접근 권한을 부여하지 않습니다. 유료 AI 호출·실제 계정 간 DB 동기화·SQL 실행·휴대폰 실물 터치는 이번 검증에 포함하지 않았습니다.
- 칼선 PDF는 RGB 이미지를 포함한 60mm 페이지와 별도 `CutContour` 색상을 제공합니다. 인쇄소에서 CMYK·도무송 규격·여백을 최종 확인해야 합니다.
- 시연 상태는 실제 매출·정산이나 신뢰할 수 있는 과금 원장으로 사용하지 않습니다. 실제 서비스에는 서버에서 가격·토큰·결제 승인을 검증하는 별도 운영 구현이 필요합니다.
